# Модель решений рекомендательного движка (v0 — проект)

Статус: **черновик для утверждения**. Код приложения пока не менять.

Слои выполняются строго по порядку. Каждый слой логируется.

---

## Слой 0. Входные данные и полнота

Нормализовать рецепт без изменения значений (не «улучшать» и не пересчитывать в другой формат без явной опции).

Рассчитать производные (для правил, не для клиента):
- `|SPH|_max`, `|CYL|_max`, spherical equivalent на глаз: `SE = SPH + CYL/2`
- anisometropia ≈ `|SE_OD − SE_OS|`
- наличие ADD / призмы / возраста

Определить **уровень результата**: A / B / C (см. `12-safety-and-escalation.md`).

---

## Слой 1. Жёсткие ограничения (hard filter)

Исключить SKU если:
1. `sphere` клиента вне `[sphere_min, sphere_max]` **и** диапазон известен с confidence ≥ from_price_list.
2. `|cyl|` выше заявленного лимита SKU (если лимит unknown — не отсекать по cyl, а пометить B).
3. Требуемый `lens_type` несовместим с задачей (пример: polar plano-only при ненулевой коррекции).
4. Клиент явно отказался от фотохрома, а SKU фотохромный (и наоборот при жёстком «только хамелеон»).
5. Бюджет жёсткий и `price_per_pair` > budget × k (k — конфиг, дефолт 1.05–1.15).
6. Для безободковой: материал/индекс с `rimless_relevance=0` **и** владелец включил жёсткий режим (иначе предупреждение, не бан).

Если диапазон SPH у SKU = unknown (Rodenstock HTML) → **не hard-pass как «подходит»**; либо исключить из автоподбора, либо только класс B с пометкой «нужна проверка по каталогу лаборатории».

---

## Слой 2. Клинические / профессиональные предупреждения

Не диагноз. Эскалация в C или предупреждение.

Пороги — **конфиг**, статус `needs_owner_approval`:

| Код | Черновик порога | Действие |
|-----|-----------------|----------|
| E_HIGH_SPH | \|SPH\| ≥ 8.00 | C или B+визит |
| E_HIGH_CYL | \|CYL\| ≥ 3.00 | B/C |
| E_ANISO | ΔSE ≥ 2.00 | C |
| E_PRISM | призма в рецепте | C |
| E_CHILD | age < 14 | C (дети) |
| E_ADD_NO_MEASURE | ADD>0 без PD/высоты | progressive/office только оценка B |
| E_UNREADABLE_RX | низкая уверенность OCR | C |
| E_CONFLICT | ответы противоречат рецепту | уточнение |

---

## Слой 3. Оценка пригодности (scoring)

Веса — конфиг. Запрещено: «дороже = лучше».

Факторы (примеры):
- соответствие use-case (daily / computer / drive / near)
- thinness_potential vs потребность (от SE + размер оправы; без оправы — мягкий вес)
- coating_tier vs glare/cleaning priority
- photochromic match + штраф обычному фотохрому для «часто за рулём» (лобовое режет УФ)
- blue_filter: мягкий плюс к «экраны», **без** обещания лечения; не поднимать агрессивно над AR+эргономикой
- stock vs rx (срок) — если клиент срочности не выражал, малый вес
- diversity penalty если 3 варианта почти одинаковы

---

## Слой 4. Коммерческая упаковка (3 варианта)

Из eligible:

1. **Практичный** — минимальная достаточная оптика под задачу и рецепт; не «намеренно плохой».
2. **Оптимальный** — лучший баланс польза/цена для сценария (герой рекомендации).
3. **Премиальный** — заметный прирост комфорта/покрытия/дизайна, объяснимый; не ради чека.

Правила портфеля:
- разные price_tier или разные ключевые фичи;
- не три 1.74 при слабой миопии;
- если budget=min_price — premium = «чуть надёжнее покрытие», не Rodenstock top.

---

## Слой 5. Объяснение

Для каждого варианта сгенерировать:
- почему подходит (связь с ответами + рецептом);
- польза простым языком;
- отличие от соседа;
- ограничения / честно;
- что подтвердить при встрече;
- из чего цена: `2 × lens + labor_estimate` (+ опции), с пометкой «оценка».

Технические имена — только в раскрываемом блоке / режиме мастера.
