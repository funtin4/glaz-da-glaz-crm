# Аудит концепции: цифровой оптик-консультант

Совет директоров не принял ТЗ «как есть». Ниже — жёсткая критика и усиленная концепция продукта **Lens Path** (рабочее имя внутри: Цифровой оптик Глаз Да Глаз).

---

## Что слабое в исходной концепции

### 1. Вопросы без рецепта — театр, не экспертиза
Пять lifestyle-вопросов без SPH/CYL/ADD дают красивый UI, но не заменяют консультанта. При −1.00 и −8.00 ответы «хочу тонкие» означают разные вещи. **Рецепт — вход №1**, не приложение.

### 2. Фиксированные 5 вопросов — лишние клики
Если клиент уже выбрал «затемнение на солнце» в приоритетах, вопрос про фотохром дублирует. Если SPH −7.5, вопрос «насколько тонкие» почти риторический: эксперт сам обязан поднять индекс. **Apple сделал бы 2–4 адаптивных шага**, не анкету.

### 3. «Три карточки равного веса» снижает конверсию
Практичный / оптимальный / премиум — понятно, но клиент снова выбирает. Лучше: **один явный «рекомендуем вам»** + два альтернативных пути (дешевле / ещё комфортнее) с объяснением *почему именно для вашего рецепта*.

### 4. Полный запрет терминов в «Подробнее» — ошибка доверия
Клиенту на карточке — человеческий язык. Но в деталях и в режиме продавца нужны индекс, покрытие, бренд: это сигнал качества и аргумент для Авито-диалога. **Два слоя языка**, не одно «упрощение».

### 5. Бюджет в конце — поздно
Если бюджет «до 8 000 за пару», нет смысла считать премиум Rodenstock и потом прятать. Бюджет — **мягкий фильтр рано** или жёсткий кошелёк в профиле сессии от менеджера.

### 6. Нет оправы — слепое пятно оптики
Безободковая / крупная / детская оправа меняет диаметр, индекс и технологию. Фото оправы без классификации почти бесполезно. Нужен быстрый тип оправы (хотя бы 3 варианта) или разметка агентом.

### 7. Каталог ≠ эксперт
«Не потерять ни одной модели» правильно для базы знаний. Но продукт не должен показывать каталог. SKU живут внутри движка; наружу — 3 решения.

### 8. Нет точки продажи
После карточек нужен CTA: «Оставить заявку», «Написать консультанту», «Записать в CRM». Иначе это красивый калькулятор, а не коммерческий продукт.

---

## Что усилить (более сильная концепция)

**Lens Path = сессия консультации**, а не страница с опросом.

1. Менеджер на Авито создаёт сессию за 20 секунд: рецепт + бюджет + заметка.
2. Клиент получает `glaz.online/select/XXXX`.
3. Видит уже «мы получили ваш рецепт» и отвечает на **короткий адаптивный путь**.
4. Получает **1 главную рекомендацию + 2 альтернативы**.
5. Нажимает «Хочу этот вариант» → лид в CRM / Telegram менеджеру.
6. Тот же движок позже отвечает в Telegram-боте и голосом.

Это ближе к **Amazon** (персональная рекомендация + почему), **Notion** (одна сущность Session, много поверхностей) и **лучшему SaaS** (engine as product, UI as channel).

## Что бы сделали разные школы

| Школа | Решение |
|-------|---------|
| **Apple** | Один hero-рекомендация, минимум текста, визуал толщины, прогресс «ещё 2 вопроса». |
| **Amazon** | «Люди с похожим рецептом выбирают…», A/B цены, допродажа покрытия. |
| **Notion** | Session / Prescription / Recommendation как блоки данных; один API — сайт, CRM, бот. |
| **SaaS elite** | Правила версионируются, метрики: доля сессий→заказ, средний чек, % апсейла. |

## Ошибочные решения, которые сознательно не делаем

- Интернет-магазин с корзиной на 205 SKU.
- Публичный прайс всех поставщиков.
- LLM вместо правил на старте (дорого, галлюцинации по диоптриям). LLM — слой общения *поверх* детерминированного эксперта.
- Жёсткая привязка только к HTML-прайсам без нормализованной онтологии (при 20 поставщиках умрёт).

## Чего не хватало в ТЗ (добавляем)

- Ввод / префилл рецепта
- Адаптивные вопросы
- Тип оправы
- Сессии с коротким кодом
- Режим продавца (техязык + маржа)
- Итоговая цена пары + работа
- CTA в CRM / мессенджер
- Версионирование правил эксперта
- Импорт прайсов как pipeline, не ручной хардкод

---

## Вердикт совета

Исходная идея **верная по направлению** (консультант, не каталог), но **слабая по входу данных и конверсии**.  
Строим **Lens Path**: рецепт → адаптивный диалог → 1+2 рекомендации → заказ в CRM.  
Экспертная система — ядро; сайт / CRM / Авито / Telegram / голос — каналы.
